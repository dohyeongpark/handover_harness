# 스택 플레이북

플레이북은 repo-mapper가 "이 스택이면 여기를 봐라"를 알려주는 참조 문서다.
언어/프레임워크별 지식을 여기에 담아, repo-mapper 에이전트 프롬프트 자체는
어떤 스택에도 과적합되지 않게 유지한다. 새 스택을 만나면 플레이북 파일만
추가하면 되고, `agents/repo-mapper.md`는 건드리지 않는다.

## 파일명 규칙

`<language>-<framework>.md` (framework가 없으면 `<language>.md`).
소문자, 하이픈 구분. 특정 프로젝트 이름이나 버전은 넣지 않는다.

- `typescript-react-vite.md`
- `java-spring-boot.md`
- `python-django.md`
- `python.md` (프레임워크 없이 순수 스크립트/배치인 경우)

한 파일이 여러 매니페스트 패턴을 다룰 수도 있다 (예: Vite와 CRA를 모두
`typescript-react.md` 하나에서 다루되 판별 신호 절에서 분기). 파일을 쪼갤지
합칠지는 "판별 신호가 겹치는가"로 정한다 — 겹치면 한 파일, 안 겹치면 별도 파일.

## 필수 section

각 플레이북은 다음 5개 절을 이 순서로, 이 제목 그대로 포함한다
(에이전트가 정해진 이름으로 찾아 읽으므로 제목을 바꾸지 않는다):

1. `## 판별 신호` — 어떤 매니페스트/설정 파일이 있으면 이 스택인가.
   `stacks[].manifest`로 남길 근거 파일 목록.
2. `## 엔트리포인트` — 엔트리포인트를 찾는 위치와 패턴. `entrypoints[].kind`별로
   "이 kind면 이 파일/패턴을 봐라"를 나열한다.
3. `## 모듈 경계` — 모듈 경계를 판단하는 관례 (디렉터리 단위 규칙, 흔한 예외).
4. `## 외부 의존성 설정 위치` — 외부 의존성이 어디서 설정되는가
   (환경변수 파일, 설정 클래스, 프로퍼티 키 패턴 등).
5. `## 빌드/실행/테스트 명령 확인 위치` — 어느 파일의 어느 필드를 보면
   빌드/실행/테스트 명령을 알 수 있는가.

## 작성 규칙

- **패턴만 적는다.** "이 프로젝트는 X를 쓴다" 대신 "이런 파일이 있으면 X를 쓰는
  것" 형태로 쓴다. 플레이북은 여러 프로젝트에 재사용된다.
- **근거를 남기는 방법을 알려주는 것이지, 근거 자체를 대신 채우는 게 아니다.**
  플레이북은 "OrderController.java의 18-35줄을 봐라"라고 말하지 않는다.
  "`@RestController`가 붙은 클래스의 `@RequestMapping` 값을 http_route_root의
  evidence로 남겨라"처럼, 어떤 신호를 찾아 evidence로 옮기라고만 안내한다.
- **없으면 없다고 쓴다.** 이 스택에 흔히 없는 개념(예: 프론트에 DB 마이그레이션)은
  해당 절에 "해당 없음"이라고 명시한다. 비워두면 에이전트가 놓친 것인지
  원래 없는 것인지 구분할 수 없다.
- **모노레포/서브모듈 변형을 다룬다.** 매니페스트가 레포 루트가 아니라
  하위 디렉터리에 있을 수 있다는 점을 판별 신호 절에서 언급한다.
